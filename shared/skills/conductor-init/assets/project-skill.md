# Initialize this project

This native Codex skill was generated by Conductor Init. Its policy source is commit
`@SOURCE_SHA@` in [assets/source](assets/source/shared/WORKFLOW.md); generator and asset
digests are recorded separately in [generation.json](generation.json).

Read the pinned common policy. Inspect project rules, overrides, authoritative task
records, checkpoints, CI/scripts and approved analytics inputs. Derive facts from those
sources and the user's scope. Do not execute project commands during setup. Missing
essential facts mean an inactive draft.

Write facts JSON in an approved scratch location. Required fields: `name`, `kind`
(`software` or `analytics`), `purpose`, `repository`, `lifecycle` (`Active`, `Parked`,
`Closed`), `task_records` (existing relative files or authoritative URIs), `checkpoint`
(relative path), and `verification`. Each contract needs `name`, `command`, `cwd`,
`prerequisites`, `expected`, and an existing relative `source` file supporting it.
Optional facts include architecture, data sources, storage and a confirmed owner with
assignment reference. Unknown optional facts stay `unknown`. A manual analytics check
can use a reproducible procedure as the command with an evidenced source document.
Never infer software checks for analytics.

From the project root, preview:

```sh
python3 .agents/skills/conductor-project-init/scripts/conductor_init.py onboard --target . --facts /approved/scratch/facts.json
```

Inspect the changes, then repeat with `--apply` when project setup is authorized.
Report blockers; do not defeat overrides, change pins, reopen Closed projects or reassign
owners implicitly. Custom verification skills remain project-owned; check their behavior
against the project contract without replacing them.

Lifecycle controls project activity. Task progress and execution state live separately
in the authoritative task records. Parked adoption starts no work. Initialization grants
no implementation, dependency installation, publication, deployment, credential, cloud,
scheduling or home/global editing authority.

After applying, verify hashes/references and repeat the preview: expect `unchanged`.
The setup checkpoint records adoption, not an invented task run. Check effective
instruction and skill discovery in a fresh native session if available; otherwise report
discovery as unverified. Local/cloud execution does not change project scope.

For an authorized rollback, preview with the same helper:
`rollback --target . --transaction .conductor/backups/<id>/transaction.json`, then add
`--apply`. Rollback refuses changed files and preserves unrelated additions. Retain
backups until the project explicitly decides their retention.
